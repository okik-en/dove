1.4.データベースの定義#

出題：2022年 春中間、2022年 春期末、2022年 夏期末、2023年 春期末、2025年 春中間教科書：pp. 1, 3 - 4

データベースという用語は多義語である。 1つは(1)としてのデータの格納庫を指す。 もう一つはOracle Databaseとか、PostgreSQLなどのデータベース(2)システムを指す。 これら2つを総称して(3)という場合もある。 インターネット上の(4)の全体は、Googleなどで(5)可能だから、 (6)規模のデータベースと言えるかもしれない。

  1. この3つがどう関係するかを図を使って説明しなさい。

1.5.データベースとファイルの違い#

出題：2021年 春期末、2022年 春中間教科書：p. 11

データをデータベースで管理することとファイル(file)で管理することの違いを考える。 データーベースは、組織体の唯一無二の共有資源としてDBMSで(1)管理されている。 したがって、同じデータが複数箇所に散在することはなく、データを(2)なしに保ちやすい。 一方、ファイルは(3)に隷属したデータ群であって、 データは(3)ごとに管理されているかから、データ間に(2)が生じたりする。 したがって、前者ではデータの(4)を保ちやすいが、後者では、保ちにくい。

  1. この違いについて、図を用いて説明しなさい。
  2. ファイル管理では問題になりやすいが、データベース管理を用いることで改善される点を1つ挙げ、 その理由を説明しなさい。

1.6.データベースの変遷#

出題：2024年 春期末、2025年 春期末教科書：pp. 11 - 13

1990年代の3強は(1)と(2)とSybaseの3つであった。 2000年になると、(1)だけが生き残り、(2)はIBMに、Sybaseは(3)に買収され、 データベースの3強は、(1)、IBM、(4)となり、国内では、(5)と(6)とが続いている。 さらに2010年に入ると大きく順位は入れ替わる。 当時であれば考えられなかった新たな企業が加わってきた、(7)である。 (7)が提供しているクラウドサービスである(8)が物凄い勢いで浸透してきた。 続く2020年代になると、(9) Cloudが登場してくる。 現在では1位、2位、3位は、(7)の(8)、(4)の(10)、(9)の(9) Cloudの3強となる。

  1. 1990年当時は、なぜ、3強時代であったのか？ その背景と理由を説明せよ。
  2. 1990年代の3強は、なぜ(1)だけになってしまったか？ (2)とSybaseの敗因と、(1)の勝因を解析せよ。
  3. 2010以降、新興企業(7)や(9)などの台頭は、データベース産業をどのように変えたか？
  4. AIの進化は、現在のデータベースにどのような影響を与えているか？
解答
  1. Oracle
  2. Informix
  3. SAP
  4. Microsoft
  5. Oracle
  6. Microsoft
  7. Amazon
  8. AWS
  9. Google
  10. Azure
  1. 1990年代は企業システム向けRDBMS市場が急成長しており、高い信頼性や性能が求められていた。 Oracle、Informix、Sybaseは先進的なRDBMSを提供し、大規模システムで広く採用されたため、3強時代と呼ばれた。
  2. Informixは経営問題や製品戦略の失敗によりIBMへ買収され、Sybaseも競争力低下によりSAPへ買収された。 一方Oracleは技術開発と市場拡大を継続し、企業向けDB市場で高いシェアを維持したため生き残った。
  3. AWSやGoogleなどがクラウド型データベースサービスを提供し、企業は自社でDBサーバを保有せずに利用できるようになった。 その結果、導入コストが下がり、スケーラビリティや運用性が向上し、DB産業の中心がクラウドへ移行した。
  4. AIの発展により大量データの分析需要が増加し、データベースの重要性が高まった。 また、ベクトル検索や生成AI向けデータ管理など新しい機能が求められるようになり、DB技術も進化している。

1.7.データベースの潮流#

出題：2024年 夏期末、2025年 夏期末教科書：pp. 11 - 13

教科書第1章の図/データベースの潮流では、横（𝑥）軸がビジネスデータ vs 非ビジネスデータとしている。

  1. では、縦（𝑦）軸は, 何を基準に設定しているのか、この基準の意も含めて答えなさい。
  2. RDBS、NoSQL、オブジェクト指向DM、XMLDB、NewSQLを、図の中に埋め込みなさい。 図（𝑥/𝑦軸）は自分で作成すること。
  3. オブジェクトデータモデル（OBDM）の利点を、RDBと比較して説明しなさい。 具体的には、RBDのどのような欠点を、OBDMが如何に解決しているのか？
  4. Tsurugiの特徴を5W1Hで説明せよ。
解答
  1. 構造化データ vs 半構造化/非構造化データ。 データを格納する際、あらかじめその構造を完全に決められるか、そうでないかという意味。

  2. 次の図を参考にするとよい（作成：@YuyaDaigen）。

  3. RDBではデータを表形式で管理するため、複雑なデータ構造を表現する際に複数表への分割や結合（JOIN）が必要となり、処理が複雑になる。 また、プログラム中のオブジェクトを表に変換する手間も生じる。 これに対しOBDMは、オブジェクトをそのまま格納でき、継承や関連などのオブジェクト指向の特徴を扱えるため、複雑なデータを自然に表現でき、開発効率や保守性を向上させる。
  4. Who
    国立研究開発法人 産業技術総合研究所（産総研）が中心となり，複数の国内企業とのコンソーシアム（Tsurugi コンソーシアム）によって開発が進められている。
    What
    次世代のトランザクション処理と分析処理の両立を目指した、高性能なリレーショナルデータベース。
    Where
    開発拠点は、日本国内の研究機関および企業。 オープンソースソフトウェアとして公開されており、世界中のどこからでも利用可能。
    When
    2023年9月にバージョン1.0.0 が公開された。 研究開発はそれ以前から長年にわたり行われている。
    Why
    従来のデータベースが抱える、多コアCPUの性能を活かしきれないという課題（スケーラビリティの限界）を解決するため開発された。 高い並列処理性能を実現し、高速なトランザクション処理を可能にすることを目的としている。
    How
    仕組みとして、インメモリ上での処理に最適化されたアーキテクチャを採用している。 トランザクションのコミットを待たずに次の処理を開始できる「遅延評価」の仕組みや、ロック処理の競合を最小限に抑える独自の並行制御技術により、圧倒的なスループットを実現している。
