11.1.ビッグデータの定義#

出題：2022年 夏中間、2023年 夏期末、2024年 夏期末、2025年 夏期末教科書：pp. 177 - 178

  1. ビッグデータの定義で広く受け入れられているVで始まる概念3つに関して、 それぞれの英単語とその意味を説明しなさい。
  2. さらに、教科書では出ていなかったもう二つのVも説明しなさい。 3Vとの関係も図示すること。
  3. ビッグデータの本質がもたらす3つの大きな変化とは何か、を詳しく説明せよ。
  4. ビッグデータの反対語は(x)と呼ばれる。 この研究分野の特徴を、簡単に説明すること。
解答
  1. Volume（量）
    扱わないといけないデータ量が膨大であること。
    Velocity（速度）
    顧客とのやり取りの中で発生するデータのペースが増大していること。
    Variety（多様性）
    取り扱わないといけないデータは様々であるということ．
  2. 真実性 (Veracity)
    データの正確性や信頼性とも言いかえられ、ノイズや欠損、不正確な情報を含むデータの中から、信頼できるデータを確保できること。 データの品質を担保することの重要性を示す。 多様（Variety）なデータには不正確なものが含まれやすいため、その「質」を問う観点として追加された．
    価値 (Value)
    データを分析することで、企業や社会にとって有益な知見や利益、新しいビジネスモデルといった「価値」を生み出せること。 ビッグデータはそれ自体が目的ではなく、価値を創出するための資源であるという考え方。 3Vで特徴づけられるデータを収集・分析する最終的な「目的」を示す要素として加えられた。

    3Vがビッグデータの「技術的な特徴」を定義するのに対し、5Vはそれに加えてデータの「品質（Veracity）」と「ビジネス上の目的（Value）」という、より実践的な側面を考慮したフレームワークと言える。

    • ビッグデータは、全てのデータを丸ごと扱う。
    • 扱うデータは乱雑でよく、外れ値や欠損値を含んでいても良い。
    • ビッグデータにより「因果関係から相関関係」へと価値観が変わる。 膨大なデータから因果関係を追うことは現実的ではないためである。
  4. スモールデータ。 ビッグデータ分析のような大規模な投資や専門知識を必要とせず、より手軽・迅速にビジネス課題の解決に繋げられる点で有効である。 専門家でなくても直接データを扱うことができるため、コストと時間をかけずに分析を始めることが可能となる。 またビッグデータと組み合わせることで、より精度の高い意思決定が可能になる。

11.4.分散データベース#

出題：小テスト

分散データベースとは何か。 また、集中型データベースと比較した利点を2つ説明せよ。

解答
分散データベースとは、複数のコンピュータにデータを分散配置し、全体として一つのデータベースのように利用する仕組みである。 利点として、サーバを追加して処理能力や容量を拡張できるためスケールアウトしやすい点がある。 また、一部のサーバに障害が発生しても他のサーバで処理を継続できるため、可用性や障害耐性が高い。

11.5.NoSQLと分散DB#

出題：2024年 夏期末、2025年 夏期末教科書：pp. 180 - 183

  1. Amazonの開発したDynamoが採用しているNoSQLデータモデルは何か、 その名前（英語名も含む）と構造・機能を、図も使って説明しなさい。
  2. GoogleのBigtableのNoSQLデータモデルは何か、 その名前（英語名も含む）と構造・機能を図も使って説明しなさい。
  3. NewSQL とは何か、NoSQLとの関係と違いを説明しなさい。NewSQLの具体的事例も複数与えること。
  4. 分散データベースの定義を図も使って与えなさい、具体的な事例も与えること。
  5. 共有データシステムとは何か、図を交えて説明しなさい。
  6. AmazonのDynamo、GoogleのBigtableが選択した共通データシステム、それぞれを説明しなさい。
解答

  1. キー・バリューデータモデル（key-value data model）。 キーとバリューのペアでデータを格納するデータ構造である。 キーとはデータを一意に識別するためのID、バリューとはキーに対応するデータ本体である。 主な機能はキーを指定することによるバリューの保存・取得・削除であり、このシンプルさにより極めて高速な読み書きが可能である。 CAP特性のうち可用性（A）と分断耐性（P）を優先し、強い一貫性（C）を犠牲にすることで、「止まらないサービス」を実現しているモデルといえる（BASE特性）。

  2. 列指向データモデル（column-oriented data model）。 多次元のマップ構造を持つモデルであり、行と列を持つテーブルでデータを管理する。 行キーはテーブル内の行を一意に識別するIDであり、行キーに付随する値は列ファミリ・列キー・時刻印付の値という具合に3次元の入れ子構造になっている。 列ファミリは関連する列をグループ化したものであり、列は列ファミリに属する具体的なデータ項目である。 全てのデータは時刻印でバージョン管理されており、「いつ書き込まれたデータか」という履歴を保持できる。 行ごとに異なる列を持つことができ、データが存在しない列はストレージを消費しないため、疎なデータを効率的に扱える。 特定の列だけをまとめて高速に読み出す処理が得意であり、数億人のユーザーの中から「メールアドレス」列だけを一覧で取得する、といった分析的なクエリに適している。 CAP特性のうち一貫性（C）と分断耐性（P）を優先し、可用性（A）をある程度犠牲にすることで、「信頼性の高いデータ分析」を実現しているモデルといえる。

11.6.NewSQL#

出題：小テスト

NewSQLは何を解決するために登場したのか。 NoSQLとの違いを含めて説明せよ（120～180字）。

解答
NewSQLは、ACID特性やSQLの利便性を維持したまま、大規模データ処理に必要なスケールアウトを実現するために登場した。 従来のRDBMSは拡張性に課題があり、一方NoSQLは高いスケーラビリティを持つが、ACID保証やSQL機能を弱める場合がある。 NewSQLは両者の長所を取り入れ、整合性と拡張性を両立することを目指している。

11.7.CAP定理#

出題：2022年 夏中間、2023年 夏期末、2024年 夏期末、2025年 夏期末教科書：pp. 183 - 188

BrewerのCAP定理に関して

  1. CAPの“C”、“A”、“P”とはそれぞれ何ですか?
  2. CAP 定理を説明しなさい。
  3. なぜ3つの性質を同時に完全には満たせないのか説明しなさい。
  4. BASE特性での“BA”、“S”、“E”が何を意味するのか、元英語と和文を与えよ。
  5. BASE特性を説明しなさい。
  6. NoSQLにおけるCAP定理の扱いを、BASE特性を使って説明しなさい。
  7. なぜNoSQLではACID特性よりもBASE特性が重視される場合があるのかを説明しなさい。
解答
  1. C
    Consistency（整合性）
    A
    Availability（可用性）
    P
    Tolerance to network partitions（分断耐性）
  4. BA
    Basically Available（基本的に可用）
    S
    Soft-state（ソフト状態）
    E
    Eventual consistency（結果整合性）
  5. CAP定理により共有データシステムの利用者は、整合性と分断耐性、可用性と分断耐性の2択を迫られる。 後者（可用性と分断耐性）を選択した際、可用性のために満たすべき原則がBASE特性である。

11.9.データマイニング#

出題：小テスト

データマイニングと統計的手法の共通点と相違点を説明せよ。 さらに、データベースとの関係について述べよ（150～200字）。

解答
データマイニングと統計的手法は、どちらも大量のデータを分析して有用な情報を得る点で共通している。 しかし、統計的手法が主に仮説を立ててその妥当性を検証するのに対し、データマイニングは事前の仮説がなくてもデータから規則性や関連性を発見し、知識発見を行う点が異なる。 また、データマイニングはデータベースに蓄積された大量データを分析対象とし、パターン発見や意思決定支援に活用される。
